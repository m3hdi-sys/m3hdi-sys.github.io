Compte-Rendu : Déploiement d'un Mini-SOC Hybride (Wazuh, Sysmon, VirusTotal & SOAR)

DomaineBlue Team / SIEM / SOAR
Parc superviséWindows & Linux Debian
TélémétrieSysmon & Auditd
Threat IntelAPI VirusTotal + Discord

1. Contexte & Architecture du Mini-SOC

L'objectif de ce projet est de concevoir de A à Z une infrastructure centralisée de détection et de réponse aux incidents (SIEM/XDR) capable de surveiller un parc hybride (postes Windows et serveurs Linux), de qualifier les attaques selon le référentiel MITRE ATT&CK et d'automatiser la remédiation (SOAR).

[Endpoint Windows + Sysmon] ──┐ ├──► [Serveur Wazuh SIEM/XDR] ◄──► [API VirusTotal (Scan Hash FIM)] [Serveur Linux + Auditd/SSH] ─┘ │ ├──► Réponse Active : Bannissement IP (iptables) └──► Script Python : Alerting temps réel (Webhook Discord)

2. Detection Engineering (Règles XML face à Atomic Red Team)

Pour dépasser les règles par défaut, les agents Windows ont été enrichis avec Sysmon. Des simulations d'attaques ont été exécutées via le framework Atomic Red Team (exécution de payloads PowerShell, dump mémoire LSASS, création de tâches planifiées) afin de rédiger des règles XML personnalisées dans local_rules.xml :

<group name="local,sysmon,mitre_attack,"> <!-- Détection d'exécution PowerShell suspecte (MITRE T1059.001) --> <rule id="100110" level="12"> <if_group>sysmon_event1</if_group> <field name="win.eventdata.commandLine" type="pcre2">(?i)(Invoke-AtomicTest|mimikatz|-enc|FromBase64String)</field> <description>[SOC ALERTE] Exécution PowerShell malveillante détectée (MITRE T1059.001)</description> <mitre><id>T1059.001</id></mitre> </rule> </group>

3. Défense Active (SOAR) : Bannissement dynamique via iptables

Face aux tentatives d'attaques par force brute (SSH / RDP), le module Active Response de Wazuh a été configuré dans ossec.conf pour déclencher automatiquement le script firewall-drop et bloquer l'adresse IP attaquante dans iptables dès que la règle de brute-force est déclenchée :

<active-response> <command>firewall-drop</command> <location>local</location> <rules_id>5712, 5720</rules_id> <timeout>600</timeout> </active-response>

4. Threat Intelligence (API VirusTotal) & Alerting Webhook Discord

Le module FIM (File Integrity Monitoring / Syscheck) surveille en temps réel les répertoires critiques. À chaque création ou modification d'un fichier, Wazuh interroge automatiquement l'API VirusTotal. En parallèle, un script Python sur-mesure (custom-discord.py) envoie un Embed formaté sur un salon Discord d'astreinte SOC avec le niveau de criticité, l'IP source, la technique MITRE ATT&CK et le résultat VirusTotal.

Compte-Rendu : Architecture Réseau Redondante (Protocole Cisco HSRP & Failover Python)

ObjectifDisaster Recovery / SLA
ProtocoleCisco HSRP (Standby v2)
Passerelle VIP192.168.10.254/24
AutomatisationScript Python de test SLA

1. Problématique & Conception Tolérante aux Pannes (Failover)

Dans un réseau d'entreprise, une passerelle par défaut unique constitue un SPOF (Single Point of Failure). Le déploiement du protocole HSRP (Hot Standby Router Protocol) permet de regrouper deux routeurs physiques (R1 Master et R2 Standby) derrière une adresse IP et MAC virtuelle unique (192.168.10.254).

2. Configuration Cisco IOS (Priorités, Préemption & Timers)

! --- Routeur R1 (Active / Master - Priorité 110 + Préemption) --- R1(config)# interface GigabitEthernet0/0 R1(config-if)# ip address 192.168.10.2 255.255.255.0 R1(config-if)# standby version 2 R1(config-if)# standby 10 ip 192.168.10.254 R1(config-if)# standby 10 priority 110 R1(config-if)# standby 10 preempt R1(config-if)# standby 10 timers 1 3 ! --- Routeur R2 (Standby / Backup - Priorité par défaut 100) --- R2(config)# interface GigabitEthernet0/0 R2(config-if)# ip address 192.168.10.3 255.255.255.0 R2(config-if)# standby version 2 R2(config-if)# standby 10 ip 192.168.10.254 R2(config-if)# standby 10 preempt R2(config-if)# standby 10 timers 1 3

3. Automatisation Python du test de bascule dynamique

Création d'un script d'audit en Python envoyant des sondes ICMP continues vers la passerelle virtuelle pour vérifier la bascule automatique de R1 vers R2 lors d'une coupure de lien :

# Extrait du script de validation de bascule HSRP import subprocess, time VIP = "192.168.10.254" while True: res = subprocess.run(["ping", "-n", "1", "-w", "500", VIP], capture_output=True) status = "UP (Continuité SLA assurée)" if res.returncode == 0 else "BASCULE HSRP EN COURS..." print(f"[{time.strftime('%H:%M:%S')}] Passerelle VIP {VIP} -> {status}") time.sleep(1)
