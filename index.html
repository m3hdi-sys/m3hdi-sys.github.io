Déploiement & Automatisation d'une Infrastructure Multi-Serveurs Conteneurisée

Conception d'un cluster de conteneurs Linux légers (LXC) sous Proxmox VE piloté à distance via une interface ChatOps (Bot Discord en Python).

1. Virtualisation & Micro-Architecture LXC (Proxmox VE)

Chaque instance applicative est isolée dans son propre conteneur Debian/Ubuntu avec adressage IPv4 statique dédié :

• CT 109 (192.168.0.50/24) : Nœud de contrôle & Bot Discord d'administration (bot-minecraft.service) • CT 107, 108, 110, 111 (192.168.0.51 à .54/24) : Instances applicatives isolées (minecraft-bedrock.service) • Administration depuis l'hôte Proxmox : pct exec, pct enter, pct push

2. Réseau, Clés SSH Asymétriques & Tunneling TCP/UDP

Le conteneur d'administration (CT 109) dialogue avec les conteneurs cibles via SSH par clés asymétriques sans mot de passe. L'exposition publique sécurisée (contournement CGNAT sans ouverture de ports FAI) est assurée par des tunnels TCP/UDP Playit.gg.

3. Automatisation ChatOps (Python Asyncio) & Parsing Journalctl

Développement d'un Bot Discord (discord.py) exécuté dans un environnement virtuel isolé (venv) :

• Commandes Slash (/mc, /maj) & composants interactifs (Boutons, Menus, Modals, Embeds temps réel) • Exécution asynchrone (asyncio.create_subprocess_shell) des ordres systemctl start/stop/restart via SSH • Script update_mc_players.py : Parsing Regex de journalctl sur la dernière heure pour extraire les sessions actives • Calcul d'uptime dynamique via ActiveEnterTimestamp systemd et extinction automatique en cas d'inactivité • Sauvegardes automatisées : Script Bash (backup-world.sh) générant des archives .tar.gz listées dans Discord

Compte-rendu : VPN Site-to-Site IPsec (Cisco)

OBJECTIF : Interconnecter deux réseaux locaux distants (LAN A 192.168.1.0/24 et LAN C 192.168.3.0/24) de manière sécurisée via un tunnel chiffré traversant un réseau WAN non sécurisé.

1. Infrastructure, Module HWIC-2T et Plan d'adressage

Trois routeurs Cisco 1941 équipés de cartes séries HWIC-2T. R2 simule l'opérateur WAN (ISP), tandis que R1 et R3 agissent comme passerelles de sécurité.

Vue physique du routeur R1 avec le module HWIC-2T installé (Cliquez pour zoomer).

Vérification de l'état UP/UP des interfaces GigabitEthernet et Serial sur R1, R2 et R3.

2. Activation de la licence SecurityK9 & Configuration IPsec

Activation du package cryptographique securityk9 sur les routeurs Cisco 1900, puis configuration des phases IKE Phase 1 (ISAKMP AES, Pre-shared key, DH Group 2) et Phase 2 (Transform-Set ESP, Crypto Map).

Activation : license boot module c1900 technology-package securityk9.
